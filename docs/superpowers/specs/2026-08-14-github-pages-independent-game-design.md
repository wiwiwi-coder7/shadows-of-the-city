# طرح انتقال مستقل بازی به GitHub Pages و Supabase

## هدف و مرز اجرا

نسخهٔ عمومی **Shadows of the City** باید مستقیماً از GitHub Pages اجرا شود و دیگر برای نمایش بازی، تصاویر، فونت‌ها، مسیرهای بازی، ذخیرهٔ پیشرفت یا APIهای بازی به میزبانی Manus وابسته نباشد. پیشرفت بازیکن فقط در همان مرورگر ذخیره می‌شود. پنل خصوصی مدیریت، آمار ناشناس و انتشار فوری overrideهای فارسی حفظ می‌شوند، اما backend آن‌ها به Supabase منتقل می‌شود.

این انتقال شامل حذف زیرساخت Manus از مسیر عمومی بازی است؛ به معنای حذف Supabase نیست. Supabase تنها backend باقی‌مانده برای عملیات خصوصی و داده‌های پویا خواهد بود. شناسه و رمز اختصاصی کنونی مالک همچنان روش ورود پنل ادمین خواهد بود.

## معماری تأییدشده

| لایه | مسئولیت | محل اجرا |
| --- | --- | --- |
| پوسته و روایت بازی | React/Vite، همهٔ ۱۲۰ گره داستان، کدکس، آلبوم، تنظیمات و انتخاب‌ها | GitHub Pages |
| مسیرها | hash route مانند `#/play`، `#/codex` و `#/admin` برای جلوگیری از ۴۰۴ در refresh یا لینک مستقیم | مرورگر / GitHub Pages |
| ذخیرهٔ پیشرفت | `localStorage` نسخه‌دار شامل گرهٔ فعلی، انتخاب‌ها، flags، unlockها، تنظیمات و زمان آخرین بازی | همان مرورگر بازیکن |
| دارایی‌ها | تصاویر صحنه، شیت شخصیت‌ها و فونت‌های فارسی داخل خروجی استاتیک منتشرشده | GitHub Pages |
| دادهٔ عمومی پویا | overrideهای فارسی منتشرشده و رخدادهای ناشناس بازی، با حداقل دسترسی لازم | Supabase |
| پنل ادمین | ورود با شناسه/رمز اختصاصی، ویرایش محتوا، override فارسی، آمار و صوت | GitHub Pages UI + Supabase Edge Functions |

> GitHub Pages تنها فایل استاتیک منتشر می‌کند؛ بنابراین مسیرهای SPA باید در مرورگر حل شوند و رفتار حساس ادمین باید خارج از مرورگر و در endpointهای محافظت‌شده اجرا شود. [1]

## تجربهٔ بازیکن و ذخیرهٔ محلی

هنگام بازشدن بازی، ذخیرهٔ معتبر موجود از `localStorage` خوانده می‌شود. گزینهٔ **Continue** گرهٔ `currentNodeId` را با تمام انتخاب‌ها، unlockها، flags و تنظیماتِ همان ذخیره باز می‌کند. پس از هر انتقال گره و هر تغییر مهم تنظیمات، ذخیره بلافاصله نوشته می‌شود. کارت Continue باید آخرین زمان بازی و درصد پیشرفت را نیز نشان دهد تا وجود ذخیره برای بازیکن روشن باشد.

اگر دادهٔ ذخیره خراب، ناشناخته یا متعلق به نسخه‌ای ناسازگار باشد، بازی آن را اجرا نمی‌کند؛ یک شروع تازه می‌سازد و پیام روشن ارائه می‌دهد. دکمهٔ «بازی جدید» همچنان پیش از جایگزینی ذخیره تأیید می‌خواهد. هیچ ذخیره‌ای به Supabase یا حساب کاربری منتقل نمی‌شود.

## امنیت Supabase و پنل ادمین

کلید service-role، راز امضای session، hashهای رمز و هر دادهٔ ادمینی فقط در secrets محیط Supabase Edge Functions می‌مانند و هرگز در repository عمومی یا bundle مرورگر قرار نمی‌گیرند. کلاینت فقط می‌تواند کلید anon عمومیِ محدودشده با RLS را داشته باشد.

Endpointهای Edge Function مسئول ورود مالک، صدور و بررسی session کوتاه‌مدت، dashboard، ذخیره و بازیابی overrideهای فارسی، ویرایش محتوای ادمین، عملیات صوت و رخدادهای telemetry خواهند بود. ورود با همان شناسه و رمز اختصاصی انجام می‌شود؛ Edge Function hash را در سمت سرور بررسی و session امضاشده صادر می‌کند. نقش session برای هر endpoint ادمین بررسی می‌شود. جداول عمومی تنها داده‌ای را برمی‌گردانند که بازیکن باید ببیند و رویداد telemetry بدون شناسهٔ شخصی ثبت می‌شود.

در طی انتقال، hash مالک به فرمت قابل‌بررسی در Edge Function مهاجرت می‌کند یا با همان شناسه و رمز فعال بازتنظیم می‌شود. این فرایند نباید هیچ مقدار رمز یا hash را در کلاینت افشا کند.

## بستهٔ استاتیک و انتشار

دارایی‌های محلی شامل تقریباً ۲۹۶ مگابایت تصویر و ۰٫۳ مگابایت فونت در ساختار مناسب خروجی Vite قرار می‌گیرند. همهٔ ارجاع‌های `/manus-storage/...` با مسیرهای base-aware در Pages جایگزین می‌شوند. configuration Vite با base repository (`/shadows-of-the-city/`) و مسیرهای hash آماده می‌شود تا فایل‌های JS/CSS و صحنه‌ها از زیرشاخهٔ Pages صحیح بارگذاری شوند.

یک workflow GitHub Actions، روی push به `main`، وابستگی‌ها را نصب می‌کند، build استاتیک را تولید می‌کند، artifact حاوی `index.html` را در ریشهٔ خروجی می‌سازد و آن را به Pages deploy می‌کند. فایل‌های source واقعی، نه فقط ZIP، باید در repository قرار بگیرند تا این workflow قابل بازتولید باشد. GitHub برای workflow سفارشی Pages از artifact با entry file در ریشه پشتیبانی می‌کند. [1]

## رفع خطای ۴۰۴

وضعیت فعلی فقط یک `index.html` هدایت‌گر دارد و در نتیجه فایل یا rewrite لازم برای مسیرهای داخلی بازی وجود ندارد. نسخهٔ جدید باید هدایت به دامنهٔ Manus را حذف کند، bundle واقعی را منتشر کند و مسیرهای بازی را به hash route منتقل کند. به این ترتیب بازکردن مستقیم بازی به صورت `https://wiwiwi-coder7.github.io/shadows-of-the-city/#/play` به سرور rewrite نیاز ندارد و GitHub Pages هرگز برای `/play` فایل جداگانه درخواست نمی‌کند.

## ترتیب انتقال

ابتدا کد عمومی از tRPC و Manus OAuth جدا می‌شود و adapterهای Supabase برای دادهٔ عمومی و endpointهای ادمین ساخته می‌شوند. سپس دارایی‌ها به خروجی استاتیک منتقل، مسیرها به hash route تبدیل و ذخیرهٔ محلی با UI قابل‌مشاهدهٔ Continue تقویت می‌شود. در ادامه workflow build/deploy و تنظیمات Pages اضافه می‌شوند. در پایان، تست‌های واحد، build استاتیک، اجرای مرورگر، refresh مسیر مستقیم، ذخیره/بازیابی، ورود مالک، override فارسی و dashboard بررسی می‌شوند.

## معیار پذیرش

| معیار | نتیجهٔ قابل‌قبول |
| --- | --- |
| اجرای بازی | لینک Pages بدون redirect به Manus، صفحهٔ اصلی و `#/play` را نمایش می‌دهد. |
| ذخیره | خروج از بازی و بازگشت به همان مرورگر، Continue را دقیقاً روی آخرین گره باز می‌کند. |
| مسیرها | باز کردن یا refresh کردن لینک‌های hash به ۴۰۴ نمی‌رسد. |
| دارایی‌ها | هیچ درخواست عمومی به `/manus-storage` یا `manus.space` برای گیم‌پلی ارسال نمی‌شود. |
| پنل | ورود با همان شناسه/رمز، ویرایش فارسی و آمار از Supabase انجام می‌شود. |
| امنیت | هیچ service-role key، session secret یا password hash در GitHub عمومی یا bundle وجود ندارد. |
| انتشار | push روی `main` یک deploy موفق Pages ایجاد می‌کند. |

## موارد خارج از محدوده

انتقال پیشرفت بین دستگاه‌ها، حساب بازیکن، همکاری چندمالک، و بازطراحی داستان خارج از این انتقال هستند. مخزن عمومی باقی می‌ماند و باید فقط موارد قابل‌انتشار را در خود نگه دارد.

## مرور داخلی مشخصات

این طرح هیچ placeholder اجرایی ندارد، وابستگی‌ها و مرزهای امنیتی را مشخص می‌کند، و مسیر static/public را از مسیر protected/admin جدا نگه می‌دارد. معیارهای پذیرش مستقیماً با هدف کاربر برای حذف Manus از مسیر بازی و نگه‌داشتن Supabase برای عملیات خصوصی منطبق‌اند.
